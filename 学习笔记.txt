第一部分  最重要的一条：Streamlit 每次都重跑整个脚本
========================================================

【现象】
在 Streamlit 里，你点一下按钮、输入一句话、上传一个文件，
只要页面有任何交互，Streamlit 就会把整个 .py 文件
从头到尾重新执行一遍。

【记法】
把它想成"每次交互都按了一次 F5"。
不是"页面还在，只是更新了一小块"，是"整篇代码重跑"。

【后果】
1. 普通变量（a = 1 这种）每轮都会被重新赋值，留不住。
2. 想留住的东西，必须放进 st.session_state。
3. 页面上的元素每轮也重新画一遍，所以"画历史"那段代码
   每轮都会跑，只要 state 里有数据，历史就一直在。

【结论】
"没聊天记录"这个问题，90% 是 state 被别人清了，
10% 是根本没存进去。不会是"Streamlit 忘了"。


--------------------------------------------------------
1.1  st.session_state 是什么
--------------------------------------------------------
一个"跨轮次"的小仓库。
只要浏览器不关、不刷新，里面的东西就一直在。

    存：st.session_state.名字 = 值
    取：st.session_state.名字
    安全取：st.session_state.get("名字")

【为什么要用 .get()】
    st.session_state.名字          名字不存在 → 直接报错 KeyError
    st.session_state.get("名字")   名字不存在 → 返回 None，不报错

所以"第一次进来要初始化"这种判断，一律用 .get()：

    if st.session_state.get("current_pdf_name") != uploaded_file.name:
        # 说明是第一次，或者换了新文件 → 初始化

【为什么不写 if "名字" not in st.session_state】
  也能用，但很容易写成下面这种翻车版：

    if "current_name" not in st.session_state or ...:
                       ^^^^^^^^^^^^
    这个键你从来没存过 → 前半句永远是 True → if 永远进
    → 每轮都重置 → 聊天记录每轮被清空

  【教训】键名只要写一次，就要全篇一致。
          存叫 current_pdf_name，查叫 current_name，
          Python 不会提醒你，它只会默默地永远为真。


--------------------------------------------------------
1.2  实战案例：没有聊天记录的那次
--------------------------------------------------------
代码里有一句：

    st.session_state.messages = [{"role":"system", ...}]

这是"整个列表换掉"，不是"加一条"。
只要这行每轮都执行，之前聊的全没了。

同一个道理，判断"要不要重置"的条件写错，
就变成了"每轮都重置"。

【自查方法】
在发请求前把列表打印出来，看终端：

    print(st.session_state.messages)

如果第二个问题时只剩 2 条（system + 这次的问题），
说明列表被清了。这是最快、最直接的定位方式，
不需要猜。


========================================================
第二部分  messages 列表的结构（和 AI 对话的底层）
========================================================
发给 AI 的永远是一个"列表"，每一项也是一本小字典：

    [
      {"role": "system",    "content": "你是……"},
      {"role": "user",      "content": "第一个问题"},
      {"role": "assistant", "content": "第一个回答"},
      {"role": "user",      "content": "第二个问题"},
    ]

三个角色：
    system     设定人设 / 说明书，放在最前面
    user       你说的话
    assistant  AI 说的话

【关键理解】
AI 本身没有记忆。它每次看到的，就是这个列表的全文。
你列表里有几轮，它就知道几轮；列表被清空，它就失忆。

所以"聊天记录"和"AI 的记忆"是同一个东西的两面。

【追加而不是替换】
    st.session_state.messages.append({...})       加一条   ✔
    st.session_state.messages = [{...}]           整个换掉 ✘

【发给前先复制一份】
    messages_to_send = list(st.session_state.messages)

这样临时往里塞文档片段，不会污染真正保存的历史。
示例（检索接入的核心）：

    if st.session_state.get("pdf_chunks"):
        picked = pick_relevant(st.session_state.pdf_chunks, prompt, k=3)
        doc_block = "\n\n".join(picked)
        messages_to_send.append({
            "role": "system",
            "content": "以下是文档中与问题最相关的片段……\n" + doc_block
        })

然后：
    messages=messages_to_send      ← 发这个
    不是 messages=st.session_state.messages

第三部分  RAG 的第一步：分块 + 检索
========================================================

--------------------------------------------------------
3.1  为什么要分块
--------------------------------------------------------
文档太长，塞不进 prompt（有长度上限，也很贵），
所以先切成小块，提问时只挑最相关的几块送进去。

    split_into_chunks(text, size=300)
    text[i : i+size]     ← 切片，每次取 size 个字

【size 大 / 小 的取舍】
    size 小 → 块数多 → 每块信息少，可能把一句话切两半
    size 大 → 块数少 → 每块信息杂，召回时不够精准

没有标准答案。文件小、问题细 → 小一点（300）；
文件大、问整体 → 大一点（600）。

【range 的步长】
    range(0, len(text), size)
    从 0 开始，每次跳 size，所以 i 会是 0, 300, 600……

--------------------------------------------------------
3.2  字符重叠打分（很粗，但是能跑）
--------------------------------------------------------

    quest_chars = set(question)
    for idx, chunk in enumerate(chunks):
        score = len(quest_chars & set(chunk))

【逐项拆开】
    set(question)          把问题拆成一堆不重复的"字"
    set(chunk)             把这一块也拆成一堆字
    &                      交集，只留"两边都有"的
    len(...)               数一数有几个 → 这就是分数

【enumerate 的作用】
    for idx, chunk in enumerate(chunks):  →  同时拿到序号和内容
    等价于 chunks[i]，但更省事，不会写错下标。

--------------------------------------------------------
3.3  排序：元组是怎么比的
--------------------------------------------------------
    scored.append((score, idx))
    scored.sort(reverse=True)
    top = scored[:k]

存的是 (分数, 序号) 这种元组。
元组比较：先比第一个，第一个相等再比第二个。

【坑】reverse=True 时，并列的会按"序号大的在前"。
结果就是：两块都 6 分，排在前面的是靠后的那块，
和问题语义真正相关的那块反被挤掉。

【这就是字符打分的上限】
它只认"字有没有出现"，不认"意思像不像"。
真正的 RAG 用向量相似度（语义），不是数重叠。

--------------------------------------------------------
3.4  这些报错是什么意思（错误分类）
--------------------------------------------------------
SyntaxError / IndentationError   → 代码写错了（少了冒号、缩进不对）
ModuleNotFoundError              → 环境问题（包没装 / 装错解释器）
NameError                        → 名字打错了或没定义
TypeError                        → 类型不对（对数字用 .append()）
AttributeError                   → 东西没有这个属性（st.sessopm_state）

【两次真实翻车】
1) score.append(...)  →  'int' object has no attribute 'append'
   score 是个数，不是列表；要往列表里加，得用 scored。
2) 函数忘写 return  →  picked 是 None  →  'NoneType' has no len()
   函数里算完了但没交出来，外面拿到的是 None。

【识错口诀】
先看最后一行是什么 Error，再定方向：
  语法类 → 那一行本身
  模块类 → 环境和安装
  其他   → 打印中间变量，看实际值

第四部分  函数与代码组织
========================================================

def 函数名(参数, 参数=默认值):
    """说明"""
    ...
    return 结果

【默认值】
    def split_into_chunks(text, size=300):
    调用时不写 size 就是 300，写了就用你给的。

【有没有 return 的区别】
    有 return → 函数给你一个值，可以 c = 函数()
    没 return → 函数返回 None，你拿到的是"空"

【缩进】
Python 靠缩进判断"谁属于谁"，一律 4 个空格，
不要混 Tab。缩进错了报 IndentationError。

--------------------------------------------------------
4.1  if __name__ == "__main__" 是干嘛的
--------------------------------------------------------
意思是："只有直接运行这个文件，下面的才执行。"

【为什么重要】
Streamlit 跑主文件时，是把它当"直接运行"处理的，
所以写在主文件里的测试代码每轮都会跑一遍。

所以测试代码要放到单独的文件里（比如 chunk_tool.py），
用 `python chunk_tool.py` 单独测，不干扰网页。

--------------------------------------------------------
4.2  pip 装的是什么
--------------------------------------------------------
pip install pypdf     ← 装"包"
pip install python    ← 错！python 是"解释器"，不是包

【一句话】pip 装的是库，解释器是另外装的。
报 ModuleNotFoundError 时，先确认是不是这个环境。

第五部分  几个真实 bug 的复盘（2026-11-20）
========================================================

--------------------------------------------------------
5.1  第 101 行：一个字母的拼写错误
--------------------------------------------------------
    st.sessopm_state.messages = [...]
        ^^^^^^^  多了个 p

运行报：
    AttributeError: module 'streamlit' has no attribute 'sessopm_state'
    Did you mean st.session_state?

【为什么危险】
它能跑 99% 的时间，只在"上传新文档"那一条路径上炸。
表现出来不是"报错"，而是"上传之后下半截页面没了"。

【教训】
AttributeError 是"执行到那一行才爆"，
它前面的行已经跑过了，后面的行一行都不会跑。
所以看到"X 之后的东西全没了"，先看 X 后面第一句。

--------------------------------------------------------
5.2  两个 uploader 抢一个变量名
--------------------------------------------------------
    with st.sidebar:
        uploaded_file = st.file_uploader("上传PDF文档", ...)      # 第 76 行

    uploaded_file = st.file_uploader("上传你的PDF文件…", ...)      # 第 87 行

【后果】
如果你在侧边栏拖了文件，第 87 行会把它覆盖成 None，
"读 PDF"那整块永远进不去 —— 但页面上看着像是成功上传了。

【教训】
一个变量只能有一个"最后写入者"。
两个控件写同一个名字 = 后写的赢，前面的白做。

--------------------------------------------------------
5.3  判断的名字和删除的名字不一致
--------------------------------------------------------
    if "pdf_content" in st.session_state:     # 判断 pdf_content
        del st.session_state.pdf_chunks        # 删 pdf_chunks

条件永远为假 → "清空"删不掉数据 → 清完还能问出旧文档的内容。

【教训】
"判断用的键名"和"操作的对象"必须是同一个。
改名的时候，全篇搜一遍旧名字（Ctrl+F）比凭记忆靠谱。

第六部分  附录：Git 与环境（2026-11-18）
========================================================

【最基本的四步】
    git status                看现在什么状态
    git add .                 把改动放进待提交区
    git commit -m "说明"      存档
    git push                  传到 GitHub

【git status 里的符号】
    ??  未跟踪（新文件，还没 add）
    !!  已忽略（被 .gitignore 挡住了，不会上传）
    M   已修改

【.gitignore】
一行一个规则，写在这儿的文件 git 永远看不见。
    .env
    __pycache__/
    *.pyc
    .streamlit/secrets.toml

【重要】推之前一定看 git status，
        列表里绝不能出现 .env 或 .streamlit/secrets.toml。
        （API key 泄露过一次，学费 43 块）

【验证某个文件是不是被忽略了】
    git check-ignore -v 文件名
    有输出 = 被忽略了；没输出 = 会被上传

【ahead / behind】
    git status -sb  →  ahead 1 表示本地比云端多 1 个提交，该 push 了

【配置】
    git config --global user.name  "sssslion"
    git config --global user.email "邮箱"
    一次一条命令，不要两行拼在一行（会报 no action specified）

【网络】
本机 github.com:443 直连不通。
走 Watt Toolkit 加速，并且：
    git config --global http.sslBackend schannel
（让 git 信任 Windows 证书库）
gh-proxy 之类只能读（clone），不能写（push 报 No anonymous write access）。
